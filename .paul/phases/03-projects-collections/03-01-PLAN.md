## Goal
Create the project/collection data model and a listing page that displays all collections as a browsable grid of project cards.

## Purpose
Enables organizing photos into named projects/series — transforming the portfolio from a flat gallery into a curated body of work. This is the foundation for the "photo dump" vision where future shoots get organized into collections.

## Output
- Extended `photos.json` with `collections` array
- Collection helper utilities for data access
- ProjectsPage component rendering a card grid of all collections
- New `/projects` route in App.jsx

<acceptance_criteria>

## AC-1: Collection Data Model
```gherkin
Given photos.json contains a collections array
When a collection entry is defined
Then it has id, name, description, coverPhotoId, photoIds, date, and tags fields
And coverPhotoId references a valid photo id
And photoIds is an array of valid photo ids
```

## AC-2: Collection Helper Utilities
```gherkin
Given collectionHelpers.js is imported
When getCollections() is called
Then it returns all collections from photos.json
When getCollectionById(id) is called with a valid id
Then it returns the matching collection object
When getCollectionCoverPhoto(collection) is called
Then it returns the photo object matching coverPhotoId
And it returns null if coverPhotoId references a non-existent photo <!-- audit-added -->
When getCollectionPhotos(collection) is called
Then it returns an array of photo objects matching photoIds in the order specified by the photoIds array <!-- audit-added -->
And it silently filters out any photoIds that reference non-existent photos <!-- audit-added -->
```

## AC-3: Projects Listing Page
```gherkin
Given a user navigates to /projects
When the page loads
Then a grid of project cards is displayed
And each card shows the cover image, collection name, description, and photo count
And the page matches the dark cinematic brutalism design system
And cards have hover interaction consistent with existing gallery patterns
And if zero collections exist, an empty state message is displayed <!-- audit-added -->
```

## AC-5: Accessibility <!-- audit-added -->
```gherkin
Given a user navigates to /projects
When the page loads
Then each project card uses semantic HTML (article element with heading)
And cover images have descriptive alt text via getAltText
And cards are keyboard-focusable with visible focus indicators
And cover images use getFallbackUrl onError handler for broken image recovery
```

## AC-4: Route Registration
```gherkin
Given the app is running
When a user visits /projects
Then the ProjectsPage component renders within the main layout (Header + Footer)
```
