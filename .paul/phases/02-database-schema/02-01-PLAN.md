  <name>Task 1: Create database schema, env validation, DB client, and Drizzle config</name>
  <files>package.json, src/db/schema.ts, src/db/index.ts, src/lib/env.ts, drizzle.config.ts, .env.example</files>
  <action>
    **Install dependencies:**
    ```
    pnpm add drizzle-orm @neondatabase/serverless zod
    pnpm add -D drizzle-kit
    ```

    **Create `src/db/schema.ts`:**
    - Define all 6 tables per CLAUDE.md spec using Drizzle's pgTable
    - Use `pgEnum` for status (processing|ready|failed|archived) and variant_type (thumb_200|web_1200|retina_2400)
    - photos: uuid PK (defaultRandom), storage_key (varchar), width/height (integer, nullable — null during processing), exif_data (jsonb, nullable), blurhash (varchar, nullable), caption (varchar, nullable), alt_text (varchar, nullable), status enum (default 'processing'), taken_at (timestamp, nullable), is_published (boolean, default false), gallery_sort_order (integer), created_at/updated_at (timestamps)
    - photo_variants: uuid PK, photo_id FK → photos (onDelete cascade), variant_type enum, storage_key, width/height (integer), format (varchar), file_size (integer), created_at
    - categories: uuid PK, name (varchar, unique), slug (varchar, unique), sort_order (integer), created_at
    - photo_categories: composite PK (photo_id, category_id), both FK → cascade
    - projects: uuid PK, title, slug (unique), description (text, nullable), cover_photo_id FK → photos (onDelete set null, nullable), is_published (boolean, default false), sort_order (integer), published_at (timestamp, nullable), created_at/updated_at
    - project_photos: composite PK (project_id, photo_id), sort_order (integer), added_at (timestamp, default now), FK cascade on both
    - Create indexes: GIN on photos.exif_data, B-tree on photos.taken_at, B-tree on photos.gallery_sort_order, composite (project_id, sort_order) on project_photos, unique on categories.slug, unique on projects.slug
    - Export all tables, enums, and inferred types (e.g., `type Photo = typeof photos.$inferSelect`)

    **Create `src/lib/env.ts`:**
    - Follow exact pattern from CLAUDE.md
    - serverSchema: DATABASE_URL (url, startsWith postgresql://), R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET_NAME, R2_PUBLIC_URL (url), ADMIN_PASSWORD_HASH (startsWith $2), JWT_SECRET (min 64)
    - clientSchema: NEXT_PUBLIC_CDN_URL (url)
    - Export serverEnv and clientEnv
    - Note: env validation will fail at import time until env vars are set. That's intentional — catches misconfig at deploy time.

    **Create `src/db/index.ts`:** <!-- audit-added: corrected import path and API pattern -->
    - Import `neon` from `@neondatabase/serverless`
    - Import `drizzle` from `drizzle-orm/neon-http` (NOT `drizzle-orm/neon-serverless` — neon-http is the correct driver for the HTTP query function returned by `neon()`)
    - Import serverEnv from src/lib/env
    - Create and export db client using config object pattern:
      ```typescript
      const sql = neon(serverEnv.DATABASE_URL);
      export const db = drizzle({ client: sql });
      ```
    - Export schema for use in queries
    - Note: `neon-http` does NOT support interactive `db.transaction()`. This is fine — app queries are reads. The seed script creates its own Pool-based connection for transactions (see Task 2).

    **Create `drizzle.config.ts`:** <!-- audit-added: corrected config pattern -->
    - Use `defineConfig` from `drizzle-kit`:
      ```typescript
      import { defineConfig } from "drizzle-kit";
      export default defineConfig({
        schema: "./src/db/schema.ts",
        out: "./drizzle",
        dialect: "postgresql",
        dbCredentials: { url: process.env.DATABASE_URL! },
      });
      ```
    - dbCredentials: use `process.env.DATABASE_URL!` directly (not serverEnv — drizzle-kit runs outside Next.js)
    - Note: `drizzle-kit generate` does NOT use dbCredentials (only reads schema) — works without DATABASE_URL. Only `drizzle-kit migrate` requires a live connection.

    **Create `.env.example`:**
    - List all required env vars with empty values and comments
    - Include DATABASE_URL, R2_*, ADMIN_PASSWORD_HASH, JWT_SECRET, NEXT_PUBLIC_CDN_URL

    **Generate migration:**
    - Run `pnpm drizzle-kit generate` to produce initial SQL migration in drizzle/

    Avoid:
    - Do NOT import serverEnv in drizzle.config.ts (it runs outside Next.js context, other vars won't exist)
    - Do NOT add uploaded_by or user_id columns anywhere
    - Do NOT use a generic "tags" table — categories handle categorization
    - Do NOT store full URLs in storage_key columns — just the path/key

<task type="auto">
  <name>Task 2: Create seed script and query functions</name>
  <files>scripts/seed.ts, src/db/queries/photos.ts, src/db/queries/categories.ts, src/db/queries/projects.ts, package.json</files>
  <action>
    **Create `scripts/seed.ts`:**
    - Read src/data/photos.json
    - Map photos.json categories to `categories` table rows:
      - portraits → { name: "Portraits", slug: "portraits", sort_order: 1 }
      - street → { name: "Street", slug: "street", sort_order: 2 }
      - travel → { name: "Travel", slug: "travel", sort_order: 3 }
    - Map photos.json photos to `photos` table rows: <!-- audit-added: clarified deterministic field mapping -->
      - title → caption (always — this is the photo's display name)
      - description → alt_text (if non-empty; otherwise use title as alt_text fallback)
      - url → storage_key (strip leading slash: "/photos/foo.jpg" → "photos/foo.jpg")
      - published → is_published
      - order → gallery_sort_order
      - date → taken_at (parse as Date)
      - width, height → null (no dimension data in JSON — will be populated by Phase 4 image processing)
      - exif_data, blurhash → null (no data in JSON — will be populated by Phase 4)
      - aspectRatio → not stored (derived from width/height at render time)
      - featured, heroImage → NOT IN SCHEMA — data is silently dropped. Phase 6 homepage will use gallery_sort_order + limit to select featured photos instead. Log a warning during seed for visibility.
      - tags → NOT IN SCHEMA — freeform tags are dropped. Categorization uses photo_categories join table only. Log a warning during seed.
      - status: set to 'ready' for all seeded photos (they're already processed)
    - Map photos.json photo.category (single string) to photo_categories join entries
    - Map photos.json collections to `projects` table rows:
      - id (slug) → slug
      - name → title
      - description → description
      - coverPhotoId → look up photo by JSON id, use its DB UUID as cover_photo_id
      - Set is_published: true, published_at: now
    - Map collection.photoIds to project_photos join entries with sort_order
    - **Seed script must create its own DB connection** — do NOT import from src/db/index.ts (which uses neon-http and triggers full env validation). Instead: <!-- audit-added: transaction-capable connection -->
      ```typescript
      import { Pool } from '@neondatabase/serverless';
      import { drizzle } from 'drizzle-orm/neon-serverless';
      const pool = new Pool({ connectionString: process.env.DATABASE_URL });
      const db = drizzle({ client: pool });
      ```
      This uses the WebSocket-based driver which supports `db.transaction()`.
    - Install `ws` as a dev dependency (`pnpm add -D ws @types/ws`) — required for @neondatabase/serverless Pool in Node.js environments.
    - Configure WebSocket before creating pool: `import ws from 'ws'; neonConfig.webSocketConstructor = ws;`
    - Use transactions for consistency: wrap all inserts in a single `db.transaction(async (tx) => { ... })`
    - Handle UUID mapping: since photos.json uses sequential string IDs ("1", "2"), create a Map<string, string> to track JSON ID → DB UUID for foreign key resolution
    - Script MUST be idempotent: TRUNCATE tables in reverse dependency order (project_photos, photo_categories, photo_variants, projects, photos, categories) using CASCADE, then insert fresh. This is the safe strategy — ON CONFLICT DO NOTHING leaves stale data. <!-- audit-added: explicit idempotency strategy -->
    - Close the pool after seeding: `await pool.end()` — prevents the script from hanging.
    - Add npm script: "db:seed": "tsx scripts/seed.ts"

    **Create `src/db/queries/photos.ts`:**
    - getPublishedPhotos(categorySlug?: string): returns photos with is_published=true, status='ready', ordered by gallery_sort_order. If categorySlug provided, join through photo_categories+categories to filter.
    - getPhotoById(id: string): returns single photo with its categories and variants
    - getFeaturedPhotos(limit?: number): returns published photos ordered by gallery_sort_order, limited (for homepage)

    **Create `src/db/queries/categories.ts`:**
    - getAllCategories(): returns categories ordered by sort_order
    - getCategoryBySlug(slug: string): returns single category

    **Create `src/db/queries/projects.ts`:**
    - getPublishedProjects(): returns published projects ordered by sort_order, with cover photo
    - getProjectBySlug(slug: string): returns project with its ordered photos (join project_photos, order by sort_order)

    **Add scripts to package.json:**
    - "db:generate": "drizzle-kit generate"
    - "db:migrate": "drizzle-kit migrate"
    - "db:seed": "npx tsx scripts/seed.ts"
    - "db:studio": "drizzle-kit studio"

    Install tsx as dev dependency for running TypeScript seed script: `pnpm add -D tsx`
    Install ws for seed script WebSocket support: `pnpm add -D ws @types/ws` <!-- audit-added -->

    Avoid:
    - Do NOT use raw SQL for queries — use Drizzle query builder
    - Do NOT add client-side query functions — all queries run server-side only
    - Do NOT import from src/db/index.ts in the seed script — it uses neon-http (no transactions) and triggers full env validation. Seed creates its own Pool-based connection. <!-- audit-added: clarified reason -->
  </action>
