<objective>
## Goal
Create the R2 storage client, presigned upload flow, and upload confirmation endpoint so that an authenticated admin can upload photos directly to Cloudflare R2 and register them in the database.

## Purpose
This is the foundation of the CMS — without object storage and upload infrastructure, the admin cannot add new photos. This plan establishes the upload path; Plan 04-02 will add the image processing pipeline that runs after confirmation.

## Output
- `src/lib/storage.ts` — R2 S3Client, presigned URL generation, storage key helpers
- `src/lib/constants.ts` — Allowed upload types, max file size
- `src/lib/session.ts` — Extended with `getSession()` helper for API route auth
- `src/app/api/uploads/presign/route.ts` — GET endpoint returning presigned PUT URL
- `src/app/api/uploads/confirm/route.ts` — POST endpoint creating photo record
</objective>

<acceptance_criteria>

## AC-1: Presigned URL Generation
```gherkin
Given an authenticated admin session
When GET /api/uploads/presign?filename=sunset.jpg&contentType=image/jpeg
Then response is 200 with JSON { data: { url, storageKey, photoId }, error: null }
And url is a valid presigned S3 PUT URL for R2
And storageKey matches pattern "photos/<uuid>/original.jpg"
And photoId is a valid UUID matching the storageKey prefix
```

## AC-2: Content Type Validation
```gherkin
Given an authenticated admin session
When GET /api/uploads/presign?filename=doc.pdf&contentType=application/pdf
Then response is 400 with JSON { data: null, error: "Unsupported file type..." }
```

## AC-3: Upload Confirmation
```gherkin
Given a file has been uploaded to R2 at the presigned storage key
When POST /api/uploads/confirm with { storageKey }
Then photoId is extracted from the storageKey UUID segment
And a photo record is created in the database with:
  - id matching the extracted photoId
  - storage_key matching storageKey
  - status = "processing"
  - is_published = false
  - gallery_sort_order = (current max + 1)
And response is 200 with JSON { data: { id, status }, error: null }
```

## AC-6: Duplicate Confirmation Handled <!-- audit-added -->
```gherkin
Given a photo record already exists for the photoId extracted from storageKey
When POST /api/uploads/confirm with the same storageKey
Then response is 409 with JSON { data: null, error: "Upload already confirmed" }
And no duplicate record is created
```

## AC-7: Oversized Upload Rejected at Confirm <!-- audit-added -->
```gherkin
Given an authenticated admin has uploaded a file exceeding MAX_UPLOAD_SIZE (50MB)
When POST /api/uploads/confirm with the storageKey of the oversized file
Then the file size is checked via HEAD request Content-Length
And response is 400 with JSON { data: null, error: "File exceeds maximum upload size..." }
And no photo record is created
```

## AC-4: Auth Protection on Upload Endpoints
```gherkin
Given an unauthenticated request (no session cookie or invalid JWT)
When accessing GET /api/uploads/presign or POST /api/uploads/confirm
Then response is 401 JSON { data: null, error: "Unauthorized" }
And no redirect occurs (API routes return JSON, not redirects)
```

## AC-5: Missing Parameters Rejected
```gherkin
Given an authenticated admin session
When GET /api/uploads/presign without filename or contentType params
Then response is 400 with JSON { data: null, error: "..." } describing missing params
```

<task type="auto">
  <name>Task 1: Install AWS SDK and create R2 storage library + constants</name>
  <files>package.json, pnpm-lock.yaml, src/lib/storage.ts, src/lib/constants.ts</files>
  <action>
    1. Install dependencies:
       ```
       pnpm add @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
       ```

    2. Create `src/lib/constants.ts`:
       - `ALLOWED_UPLOAD_TYPES`: Set of allowed MIME types — `image/jpeg`, `image/png`, `image/webp`, `image/avif`, `image/tiff`
       - `MAX_UPLOAD_SIZE`: 50MB (50 * 1024 * 1024) — reasonable limit for high-res photography
       - `VARIANT_CONFIGS`: Export for future use in 04-02 (thumb_200, web_1200, retina_2400 with max dimensions and format)

    3. Create `src/lib/storage.ts`:
       - Import `serverEnv` from `@/lib/env` for R2 credentials
       - Create lazy-initialized S3Client configured for R2:
         - endpoint: `https://${serverEnv.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`
         - region: `"auto"`
         - credentials from serverEnv (R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY)
       - `generateStorageKey(filename: string)`: returns `{ photoId: string, storageKey: string }`
         - Generate UUID via `crypto.randomUUID()`
         - Extract extension from filename (lowercase, strip dots)
         - Return storageKey as `photos/${photoId}/original.${ext}`
       - `createPresignedUploadUrl(storageKey: string, contentType: string)`: returns Promise<string>
         - Uses PutObjectCommand with bucket from serverEnv.R2_BUCKET_NAME
         - Sets ContentType on the command
         - Signs with getSignedUrl, expiresIn: 300 (5 minutes)
         - **CRITICAL:** Pass `signableHeaders: new Set(["content-type"])` to getSignedUrl options — without this, the Content-Type is NOT included in the signature and a client can upload any content type regardless of what was validated at presign time <!-- audit-added -->
       - `headObject(storageKey: string)`: returns Promise<`{ exists: boolean, contentLength?: number }`> <!-- audit-added: returns size for confirm validation -->
         - Uses HeadObjectCommand to verify a file exists in R2
         - Returns `{ exists: true, contentLength }` if found (contentLength from response ContentLength)
         - Returns `{ exists: false }` if NotFound error, throws on other errors
       - `extractPhotoIdFromKey(storageKey: string)`: returns `string | null` <!-- audit-added -->
         - Parses UUID from storageKey using strict regex: `^photos/([0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})/original\.(jpg|jpeg|png|webp|avif|tiff)$`
         - Returns the UUID capture group, or null if storageKey doesn't match pattern

    Avoid:
    - Do NOT eagerly instantiate the S3Client at module level — use a lazy getter function so the module can be imported without triggering env validation in contexts that don't need storage
    - Do NOT use aws-sdk v2 (deprecated) — use @aws-sdk/client-s3 v3
    - Do NOT store the CDN URL in storage.ts — CDN resolution happens at render time per CLAUDE.md
  </action>
  <verify>
    - `pnpm exec tsc --noEmit` passes with no type errors
    - `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` appear in package.json dependencies
    - storage.ts exports: getR2Client, generateStorageKey, createPresignedUploadUrl, headObject, extractPhotoIdFromKey
    - constants.ts exports: ALLOWED_UPLOAD_TYPES, MAX_UPLOAD_SIZE, VARIANT_CONFIGS
  </verify>
  <done>AC-1 partially satisfied (storage key generation), AC-2 partially satisfied (ALLOWED_UPLOAD_TYPES defined)</done>
</task>

<task type="auto">
  <name>Task 2: Create presign and confirm API endpoints with session-based auth</name>
  <files>src/lib/session.ts, src/app/api/uploads/presign/route.ts, src/app/api/uploads/confirm/route.ts</files>
  <action>
    1. Extend `src/lib/session.ts` with a `getSession()` helper for API route auth:
       ```
       export async function getSession(): Promise<JWTPayload | null>
       ```
       - Import `cookies` from `next/headers`
       - Read JWT_SECRET from process.env (not env.ts, matching auth pattern)
       - Get session cookie, verify with verifySession()
       - Return payload on success, null on failure (expired, missing, invalid)
       - This provides a clean auth guard for any API route: `const session = await getSession(); if (!session) return 401;`

    2. Create `src/app/api/uploads/presign/route.ts` (GET):
       - Call getSession() — return 401 JSON if null
       - Parse query params: `filename` (required), `contentType` (required)
       - Validate both params present — return 400 if missing
       - Validate contentType against ALLOWED_UPLOAD_TYPES — return 400 if unsupported
       - Call generateStorageKey(filename) to get { photoId, storageKey }
       - Call createPresignedUploadUrl(storageKey, contentType) to get presigned URL
       - Return 200: `{ data: { url, storageKey, photoId }, error: null }`
       - Wrap in try/catch — return 500: `{ data: null, error: "Failed to generate upload URL" }`

    3. Create `src/app/api/uploads/confirm/route.ts` (POST):
       - Call getSession() — return 401 JSON if null
       - Parse JSON body: `{ storageKey: string }` <!-- audit-added: removed photoId param, derive from key -->
       - Call extractPhotoIdFromKey(storageKey) — return 400 if null ("Invalid storage key format"). This validates the key matches the strict UUID + extension regex AND extracts the photoId in one step <!-- audit-added -->
       - Check if photo record with this photoId already exists — return 409 if found ("Upload already confirmed") <!-- audit-added: idempotency guard -->
       - Call headObject(storageKey) to verify file exists in R2:
         - If `exists` is false → return 400 ("File not found in storage")
         - If `contentLength` exceeds MAX_UPLOAD_SIZE → return 400 ("File exceeds maximum upload size of 50MB") <!-- audit-added: size enforcement -->
       - Query MAX(gallery_sort_order) from photos table, set new order to max + 1 (or 1 if no photos)
       - Insert into photos table:
         - id: photoId (extracted from storageKey, NOT defaultRandom) <!-- audit-added: derived, not client-supplied -->
         - storageKey: storageKey
         - status: "processing"
         - isPublished: false
         - gallerySortOrder: calculated value
         - All other fields null/default (width, height, exifData, blurhash, caption, altText, takenAt set during processing in 04-02)
       - Return 200: `{ data: { id: photoId, status: "processing" }, error: null }`
       - Error handling with specific status codes: <!-- audit-added: error differentiation -->
         - 401: Unauthorized (no/invalid session)
         - 400: Invalid storage key format, file not found, file too large, missing params
         - 409: Upload already confirmed (duplicate photoId)
         - 500: Unexpected internal error (R2 network failure, DB write failure)

    Avoid:
    - Do NOT trigger image processing in the confirm endpoint (that's Plan 04-02)
    - Do NOT modify middleware.ts matcher — API routes use inline auth via getSession() to return proper 401 JSON instead of redirects
    - Do NOT import env.ts in session.ts — continue using process.env directly for JWT_SECRET to maintain Edge compatibility
    - Do NOT use NextRequest type for route handlers — use standard Request (Next.js App Router convention for route.ts)
  </action>
  <verify>
    - `pnpm exec tsc --noEmit` passes
    - `pnpm build` completes without errors
    - Manually verify endpoint behavior (requires R2 credentials in .env.local):
      - Unauthenticated GET /api/uploads/presign → 401 JSON
      - Authenticated GET /api/uploads/presign?filename=test.jpg&contentType=image/jpeg → 200 with presigned URL
      - Authenticated GET /api/uploads/presign?contentType=application/pdf → 400 rejected
      - Authenticated POST /api/uploads/confirm with valid storageKey → 200 with photo record
      - POST /api/uploads/confirm with same storageKey again → 409 duplicate <!-- audit-added -->
      - POST /api/uploads/confirm with malformed storageKey → 400 invalid format <!-- audit-added -->
  </verify>
  <done>AC-1 satisfied (presigned URL flow works end-to-end), AC-2 satisfied (invalid types rejected), AC-3 satisfied (confirm creates photo record with derived photoId), AC-4 satisfied (401 for unauthenticated), AC-5 satisfied (400 for missing params), AC-6 satisfied (duplicate confirm returns 409), AC-7 satisfied (oversized files rejected)</done>
