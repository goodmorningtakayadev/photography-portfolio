<objective>
## Goal
Implement single-admin authentication: password verification, JWT session management, middleware route protection, and a login page.

## Purpose
The admin CMS (Phase 5) requires authentication. This phase establishes the auth boundary so all subsequent admin work is protected from the start. Without auth, admin routes would be publicly accessible.

## Output
- `src/lib/auth.ts` — bcrypt password verification helper
- `src/lib/session.ts` — JWT sign/verify + cookie config (Edge-compatible)
- `src/app/api/auth/login/route.ts` — POST endpoint that validates password and sets session cookie
- `src/app/api/auth/logout/route.ts` — POST endpoint that clears session cookie
- `src/middleware.ts` — protects `/admin/*` routes, redirects to `/login` if unauthenticated
- `src/app/login/page.tsx` — login page with password form
</objective>

## Architecture Notes (from CLAUDE.md)
- Single admin, no users table. Password hash in ADMIN_PASSWORD_HASH env var.
- JWT contains `{ role: "admin", iat, exp }` — no user ID.
- Session expiry: 7 days. No refresh tokens.
- Login page at `/login` (outside admin route group).
- Middleware protects `/(admin)` routes.
- Do NOT install Auth.js, NextAuth, Lucia, or any auth library.

## AC-1: Valid Password Authentication
```gherkin
Given the server has ADMIN_PASSWORD_HASH set in environment
When a POST request to /api/auth/login sends the correct password
Then the response is 200 with a Set-Cookie header containing an HTTP-only session cookie
And the cookie contains a valid JWT with { role: "admin" } and 7-day expiry
```

## AC-2: Invalid Password Rejection
```gherkin
Given the server has ADMIN_PASSWORD_HASH set in environment
When a POST request to /api/auth/login sends an incorrect password
Then the response is 401 with JSON body { error: "Invalid password" }
And no session cookie is set
```

## AC-3: Route Protection
```gherkin
Given a request to any path matching /admin/*
When the request has no valid session cookie
Then the response redirects (307) to /login
```

```gherkin
Given a request to any path matching /admin/*
When the request has a valid session cookie with unexpired JWT
Then the request proceeds to the route handler
```

## AC-4: Logout
```gherkin
Given an authenticated admin with a session cookie
When a POST request is sent to /api/auth/logout
Then the session cookie is cleared (Set-Cookie with maxAge=0)
And subsequent requests to /admin/* redirect to /login
```

## AC-5: Login Page Functionality
```gherkin
Given a user navigates to /login
When they enter the correct password and submit
Then they are redirected to /admin/dashboard
And a session cookie is set
```

```gherkin
Given a user navigates to /login
When they enter an incorrect password and submit
Then an error message is displayed
And they remain on /login
```

<task type="auto">
  <name>Task 1: Install dependencies and create auth/session helpers</name>
  <files>package.json, src/lib/auth.ts, src/lib/session.ts</files>
  <action>
    1. Install dependencies:
       - `pnpm add bcryptjs jose`
       - `pnpm add -D @types/bcryptjs`

    2. Create `src/lib/auth.ts`:
       - Export `verifyPassword(password: string, hash: string): Promise<boolean>` using `bcrypt.compare`
       - This file imports bcryptjs — it is NOT Edge-compatible and must not be imported in middleware

    3. Create `src/lib/session.ts` (Edge-compatible — no bcrypt, no env.ts import):
       - Export cookie name constant: `SESSION_COOKIE = "session"`
       - Export `createSession(secret: string): Promise<string>`:
         - Uses `jose.SignJWT` with payload `{ role: "admin" }`
         - Algorithm: HS256
         - Expiration: 7 days (`7d`)
         - Signs with `new TextEncoder().encode(secret)`
       - Export `verifySession(token: string, secret: string): Promise<JWTPayload>`:
         - Uses `jose.jwtVerify` with same secret encoding
         - Returns the decoded payload
         - Throws on invalid/expired token
       - Export cookie config object for use in API routes:
         ```
         { httpOnly: true, secure: process.env.NODE_ENV === "production", sameSite: "lax", path: "/", maxAge: 60 * 60 * 24 * 7 }
         ```

    **Why session.ts is separate from auth.ts:**
    The middleware runs in Edge Runtime where bcryptjs cannot load. By isolating JWT logic in session.ts (which only imports `jose`), the middleware can import session.ts without pulling in Node.js-only dependencies.

    **Why session.ts does NOT import env.ts:**
    `src/lib/env.ts` eagerly validates ALL server env vars at import time (DATABASE_URL, R2_*, etc.). In Edge Runtime, not all these vars may be available. Session functions accept `secret` as a parameter instead — callers pass `serverEnv.JWT_SECRET` (API routes) or `process.env.JWT_SECRET` (middleware).
  </action>
  <verify>
    - `pnpm exec tsc --noEmit` passes with no errors in auth.ts and session.ts
    - Both files export the expected functions (manual code review)
  </verify>
  <done>AC-1 and AC-2 dependencies satisfied: password verification and session management helpers exist</done>
</task>

<task type="auto">
  <name>Task 2: Create API routes and middleware</name>
  <files>src/app/api/auth/login/route.ts, src/app/api/auth/logout/route.ts, src/middleware.ts</files>
  <action>
    1. Create `src/app/api/auth/login/route.ts`:
       - Export async `POST(request: Request)`
       - Wrap entire handler in try-catch <!-- audit-added: must-have error handling -->
       - Parse JSON body: `{ password: string }`
       - Validate body — if password missing or not a string, fall through to generic error response
       - Import `verifyPassword` from `@/lib/auth`, `createSession`, `SESSION_COOKIE`, cookie config from `@/lib/session`
       - Do NOT import from `@/lib/env` — access `process.env.ADMIN_PASSWORD_HASH!` and `process.env.JWT_SECRET!` directly <!-- audit-added: decouples auth from R2/storage env validation -->
       - Call `verifyPassword(password, process.env.ADMIN_PASSWORD_HASH!)`
       - On failure: return `NextResponse.json({ data: null, error: "Invalid credentials" }, { status: 401 })` <!-- audit-changed: generic message, { data, error } shape -->
       - On success: create session token with `createSession(process.env.JWT_SECRET!)`
       - Set cookie using `response.cookies.set(SESSION_COOKIE, token, cookieConfig)`
       - Return `NextResponse.json({ data: null, error: null })` <!-- audit-changed: { data, error } shape -->
       - In catch block: log the actual error server-side, return `NextResponse.json({ data: null, error: "Invalid credentials" }, { status: 401 })` <!-- audit-added: same response shape for all failures — prevents info leakage -->

       **Security: All failure modes (wrong password, malformed body, internal error) MUST return the same generic response shape and status code.** Do not distinguish between "invalid JSON", "missing password", "wrong password", or "bcrypt error" in the response. Differentiate only in server-side logs (`console.error`).

    2. Create `src/app/api/auth/logout/route.ts`:
       - Export async `POST()`
       - Create response with `NextResponse.json({ data: null, error: null })` <!-- audit-changed: { data, error } shape -->
       - Delete cookie: `response.cookies.set(SESSION_COOKIE, "", { ...cookieConfig, maxAge: 0 })`
       - Return response

    3. Create `src/middleware.ts` (Edge-compatible):
       - Import `verifySession`, `SESSION_COOKIE` from `@/lib/session` (NOT from auth.ts)
       - Do NOT import from `@/lib/env` (eager validation breaks Edge)
       - Do NOT import from `@/lib/auth` (bcryptjs breaks Edge)
       - Read `process.env.JWT_SECRET` directly
       - **If `JWT_SECRET` is undefined: fail closed — redirect to `/login`. Do NOT call `NextResponse.next()`. Log a warning.** <!-- audit-added: must-have fail-closed behavior -->
       - Export `config.matcher`: `["/admin/:path*"]`
       - In the middleware function:
         - Get session cookie from `request.cookies.get(SESSION_COOKIE)`
         - If no cookie: redirect to `/login`
         - If cookie exists: try `verifySession(cookie.value, jwtSecret)`
         - On verification failure (expired/invalid): clear the stale session cookie on the redirect response, then redirect to `/login` <!-- audit-added: clear stale cookies -->
         - On success: call `NextResponse.next()` to proceed

    **Avoid:**
    - Importing bcryptjs in middleware (Edge incompatible)
    - Importing env.ts in middleware (eager validation of all vars)
    - Importing env.ts in auth API routes (triggers validation of R2/storage vars that may not be set yet) <!-- audit-added -->
    - Using jsonwebtoken package (CommonJS issues with Edge runtime)
    - Returning different error messages for different failure modes in login endpoint <!-- audit-added -->
  </action>
  <verify>
    - `pnpm exec tsc --noEmit` passes
    - `curl -X POST http://localhost:3000/api/auth/login -H "Content-Type: application/json" -d '{"password":"wrong"}' ` returns 401
    - `curl -X POST http://localhost:3000/api/auth/login -H "Content-Type: application/json" -d '{"password":"correct"}' ` returns 200 with Set-Cookie header (requires correct ADMIN_PASSWORD_HASH in .env)
    - Visiting /admin/anything in browser redirects to /login
  </verify>
  <done>AC-1, AC-2, AC-3, AC-4 satisfied: login endpoint authenticates, logout clears session, middleware protects admin routes</done>
