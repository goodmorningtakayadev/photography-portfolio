<objective>
## Goal
Create an interactive CLI content management tool that enables adding photos, managing collections, and toggling draft/publish state — all without editing JSON or code by hand.

## Purpose
Phase 4 of v0.1: removes the developer-only barrier to content updates. The photographer can manage their portfolio from the terminal with guided prompts, making the site a viable ongoing photo dump as intended in PROJECT.md.

## Output
- `scripts/manage-content.js` — unified CLI tool with subcommands
- Updated `photos.json` schema with `published` field
- Gallery/Home filtering to respect publish state
- New npm scripts: `add-photo`, `add-collection`, `manage-content`
</objective>

## AC-1: Add Photo via CLI
```gherkin
Given the user runs `npm run add-photo`
When they follow the interactive prompts (file path, title, category, description, tags)
Then the photo file is copied to public/photos/
And a new entry is appended to photos.json with a unique ID
And the optimization script runs automatically producing thumbnail + display WebP variants
And the photo appears in the gallery after `npm run dev`
```

## AC-2: Manage Collections via CLI
```gherkin
Given the user runs `npm run add-collection`
When they provide collection name, description, select photos, cover photo, date, and tags
Then a new collection entry is added to photos.json
And the collection appears in the Gallery "Projects" category view
```

## AC-3: Draft/Publish Filtering
```gherkin
Given photos.json contains photos with `"published": false`
When the gallery, home page, or collections render
Then only published photos are displayed
And draft photos are excluded from all public views
And existing photos without a published field default to published (backwards compatible)
```

## AC-4: Content Listing and Management
```gherkin
Given the user runs `npm run manage-content`
When they select "list photos" or "list collections"
Then they see a formatted table of all content with ID, title, status, and category
And they can toggle draft/publish state for any photo
```

## AC-5: Error Handling and Data Safety <!-- audit-added -->
```gherkin
Given the user provides an invalid file path to add-photo
When the CLI validates the input
Then an error message is displayed and photos.json is NOT modified

Given an optimization failure occurs after file copy
When the CLI detects the error
Then the copied photo file is removed
And photos.json remains in its pre-operation state
And the user sees a clear error message

Given the user provides a filename that already exists in public/photos/
When the CLI detects the collision
Then it appends a numeric suffix to the filename
And the photo is saved with the unique name
```

<task type="auto">
  <name>Task 1: Create content management CLI with add-photo and add-collection commands</name>
  <files>scripts/manage-content.js, package.json</files>
  <action>
    Create `scripts/manage-content.js` using Node.js built-in `readline/promises` (no new dependencies).

    **Subcommands** (detected via process.argv[2]):
    - `add-photo` — interactive prompts:
      1. Source file path (validate file exists, is image)
      2. Title (required)
      3. Category (present existing categories from photos.json, user selects)
      4. Description (optional)
      5. Tags (comma-separated, optional)
      6. Aspect ratio (portrait/landscape, auto-detect from image dimensions via sharp)
      7. Featured (yes/no, default no)
      8. Published (yes/no, default yes)
      9. Collection (optional — list existing collections or skip)
      After prompts:
      - Generate next sequential ID (max existing ID + 1)
      - Sanitize filename: lowercase, replace spaces/special chars with hyphens, strip path-traversal sequences (../, ./), keep only [a-z0-9\-\.] <!-- audit-added -->
      - Check for filename collision in public/photos/ — if exists, append numeric suffix (e.g., photo-2.jpg) <!-- audit-added -->
      - Copy file to `public/photos/{sanitized-filename}.jpg`
      - Add entry to photos.json photos array
      - If collection selected, add photo ID to that collection's photoIds
      - Write photos.json safely: write to photos.json.tmp first, then rename to photos.json (atomic replacement to prevent corruption on crash) <!-- audit-added -->
      - Run optimization via child_process.execSync(`node scripts/optimize-images.js`)
      - On optimization failure: remove the copied photo file and revert photos.json from .tmp backup, print error, exit cleanly <!-- audit-added -->
      - Print summary of what was added

    - `add-collection` — interactive prompts:
      1. Name (required)
      2. Description (optional)
      3. Date (YYYY-MM format, default current month)
      4. Tags (comma-separated, optional)
      5. Select photos (show list of photos by title, multi-select by ID)
      6. Cover photo (select from chosen photos)
      After prompts:
      - Generate slug ID from name (lowercase, hyphenated, strip non-alphanumeric except hyphens)
      - Check slug collision — if exists, append numeric suffix (e.g., gold-tone-2) <!-- audit-added -->
      - Write photos.json safely via temp file + rename pattern (same as add-photo) <!-- audit-added -->
      - Add collection entry to photos.json collections array
      - Print summary

    - `manage` — interactive menu:
      1. List all photos (table: ID, title, category, published, collections)
      2. List all collections (table: ID, name, photo count, date)
      3. Toggle publish state for a photo (select by ID, flip published boolean)
      4. Exit
      - All JSON writes in manage subcommand must also use temp file + rename pattern <!-- audit-added -->

    **Package.json scripts to add:**
    ```json
    "add-photo": "node scripts/manage-content.js add-photo",
    "add-collection": "node scripts/manage-content.js add-collection",
    "manage-content": "node scripts/manage-content.js manage"
    ```

    **Validation rules:**
    - Source file must exist and be .jpg, .jpeg, or .png
    - Title must not be empty
    - Category must match existing category ID
    - Collection ID must not duplicate existing
    - Photo ID must be unique

    **JSON safety pattern (all subcommands):** <!-- audit-added -->
    Before any mutation of photos.json:
    1. Read current photos.json
    2. Write updated content to photos.json.tmp
    3. Rename photos.json.tmp → photos.json (atomic on POSIX, near-atomic on Windows)
    4. On any error: leave original photos.json untouched, clean up .tmp if it exists

    **Avoid:**
    - Adding new npm dependencies (use readline/promises + sharp which is already installed)
    - Complex async patterns — keep it sequential and simple
    - Modifying the optimize-images.js script (call it as-is)
    - Writing directly to photos.json without the temp file pattern (corruption risk) <!-- audit-added -->
  </action>
  <verify>
    1. `node scripts/manage-content.js add-photo` launches interactive prompts without errors
    2. `node scripts/manage-content.js add-collection` launches interactive prompts without errors
    3. `node scripts/manage-content.js manage` shows menu without errors
    4. After adding a test photo, photos.json contains new entry and optimized WebP files exist
  </verify>
  <done>AC-1 satisfied: photos can be added via CLI. AC-2 satisfied: collections can be created via CLI. AC-4 satisfied: content can be listed and managed. AC-5 satisfied: errors handled gracefully, data protected.</done>
