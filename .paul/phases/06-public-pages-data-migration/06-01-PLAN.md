<objective>
## Goal
Migrate the homepage and gallery page from static JSON data (`src/data/photos.json`) to database-driven content served via server components, with CDN image delivery from R2 variants. The about page is also converted to a server component (trivial — no data changes).

## Purpose
This completes the data source swap: the admin CMS populates Postgres, and now public pages read from it instead of static JSON. After this plan, the photographer can manage content through the admin interface and see it reflected on the public site.

## Output
- CDN-aware photo adapter layer mapping DB objects to component-compatible view shapes
- Homepage fetching featured photos + categories from Postgres
- Gallery page fetching all published photos + categories from Postgres
- All existing visual design, animations, and behavior preserved pixel-identical
</objective>

## AC-3: Image URLs Resolve via CDN
```gherkin
Given a photo has variants (thumb_200, web_1200) stored in R2
When a component calls getImageUrl(photo, 'thumbnail')
Then the returned URL is NEXT_PUBLIC_CDN_URL + thumb_200 variant storage key
When a component calls getImageUrl(photo, 'display')
Then the returned URL is NEXT_PUBLIC_CDN_URL + web_1200 variant storage key
When a component calls getImageUrl(photo, 'full')
Then the returned URL is NEXT_PUBLIC_CDN_URL + original storage key
```
