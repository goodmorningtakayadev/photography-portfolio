<objective>
## Goal
Add SEO infrastructure and performance optimizations to make the portfolio production-ready before deployment.

## Purpose
The site has zero SEO presence (no OG tags, no sitemap, no structured data) and ships a monolithic ~299KB bundle with no code splitting. These are blocking issues for production — search engines can't properly index the site and initial load is heavier than necessary.

## Output
- Complete SEO meta tags (Open Graph, Twitter Cards, structured data)
- sitemap.xml and robots.txt for search engine crawling
- Route-based code splitting reducing initial bundle size
- Hero image preload and resource hints for faster perceived load
- Optimized Vite build configuration
</objective>

  <action>
    **index.html — Add meta tags to `<head>`:**
    - Open Graph tags: og:title, og:description, og:image, og:type (website), og:url
    - Twitter Card tags: twitter:card (summary_large_image), twitter:title, twitter:description, twitter:image
    - Canonical URL: `<link rel="canonical">`
    - JSON-LD structured data script block with @type Person schema:
      - name, url, description, sameAs (Instagram link if available)
      - @type WebSite with name and url
    - Use placeholder domain `https://example.com` for URLs — will be updated in 05-02 when deployment domain is known
    - Theme color meta tag matching the site's dark theme (#0a0a0a or similar from CSS variables)
    - For og:image, use an ABSOLUTE URL (OG protocol requires this): `https://example.com/photos/optimized/{id}-display.webp` — pick a representative published photo. Relative paths silently fail on social media crawlers. <!-- audit-added: must-have #2 — og:image absolute URL -->

    **public/robots.txt — Create:**
    ```
    User-agent: *
    Allow: /
    Sitemap: https://example.com/sitemap.xml
    ```

    **public/sitemap.xml — Create:**
    - Standard XML sitemap with 3 URLs: /, /gallery, /about
    - Use placeholder domain `https://example.com`
    - Set changefreq: monthly for home, weekly for gallery, monthly for about
    - Set priority: 1.0 for home, 0.8 for gallery, 0.6 for about
    - Include `<lastmod>` date on each entry (use today's date: 2026-03-23) — Google prioritizes lastmod over changefreq/priority <!-- audit-added: strongly-recommended #4 — sitemap lastmod -->

    **Avoid:**
    - Do NOT add react-helmet or any new dependencies — meta tags go in static index.html
    - Do NOT hardcode a real domain — use placeholder for now
  </action>

<task type="auto">
  <name>Task 2: Performance optimization — code splitting, preloads, build config</name>
  <files>src/App.jsx, vite.config.js, index.html</files>
  <action>
    **src/App.jsx — Route-based code splitting:**
    - Import `lazy` and `Suspense` from React
    - Replace static imports of GalleryPage and About with:
      ```
      const GalleryPage = lazy(() => import('./pages/GalleryPage'))
      const About = lazy(() => import('./pages/About'))
      ```
    - Keep Home as static import (it's the landing page, should load immediately)
    - Wrap `<Routes>` in `<Suspense fallback={null}>` (no visible loading spinner — pages load fast enough)
    - Keep all other imports unchanged (Header, Footer, Router, global.css)

    **vite.config.js — Build optimization:**
    - Add `build` config with:
      - `rollupOptions.output.manualChunks`: split `react` + `react-dom` + `react-router-dom` into a `vendor` chunk
      - This separates framework code (rarely changes) from app code (changes often) for better caching
    - Do NOT add compression plugins — Vercel handles gzip/brotli at CDN level

    **index.html — Resource hints and preloads:**
    - Add `<link rel="dns-prefetch" href="https://api.web3forms.com">` for contact form
    - Add `<link rel="preload" href="/photos/vintage-aesthetics-3.jpg" as="image">` for the hero image — this is the ACTUAL hero image path (Home.jsx uses `getImageUrl(heroPhoto, 'full')` which returns the original JPG `photo.url`, NOT a WebP variant). Do NOT use type="image/webp" since this is a JPG. <!-- audit-added: must-have #1 — hero preload corrected to match actual loaded asset -->
    - Note: if the hero image changes in photos.json, this preload path must be updated manually

    **Avoid:**
    - Do NOT add any new npm dependencies
    - Do NOT change the visual appearance of any page
    - Do NOT modify page components beyond the lazy import change
    - Do NOT add a visible loading spinner/skeleton — the site is small enough that lazy chunks load near-instantly
  </action>
  <verify>

    3. Check App.jsx uses React.lazy for GalleryPage and About
    4. Check index.html has dns-prefetch and preload link tags
    5. Check vite.config.js has manualChunks configuration
    6. Compare main chunk size to pre-split baseline (~260KB JS) — confirm meaningful reduction <!-- audit-added: strongly-recommended #3 — build size comparison -->
    7. Run `npm run preview` and verify all 3 routes load correctly in production build <!-- audit-added: strongly-recommended #2 — production build verification -->
  </verify>
  <done>AC-4, AC-5 satisfied: Route-based code splitting active with separate chunks; hero preload and resource hints in place</done>

## KNOWN LIMITATIONS <!-- audit-added: strongly-recommended #1 — SPA meta tag limitation -->
- SPA meta tag sharing: All 3 routes serve the same static index.html. Social media crawlers (Facebook, Twitter, LinkedIn) do not execute JavaScript, so every shared URL will display identical OG tags (title, description, image). Per-route meta tags require SSR or prerendering (explicitly out of scope). This is acceptable for a personal portfolio where the home page OG tags represent the site adequately.
