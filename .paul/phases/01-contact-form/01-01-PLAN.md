## AC-2: Client-Side Validation
```gherkin
Given the user attempts to submit the form
When any required field is empty or email format is invalid
Then inline error messages appear below the invalid fields
And the form does not submit
And error states use the ember accent color for visibility
```

## AC-3: Successful Submission
```gherkin
Given the user fills all fields with valid data
When they submit the form
Then the form sends data to Web3Forms API
And a success message is displayed
And the form fields are cleared
```

## AC-4: Submission Error Handling
```gherkin
Given the form is filled with valid data
When submission fails (network error, API error, or timeout)
Then an error message is displayed to the user
And the form data is preserved (not cleared)
And the user can retry submission
```

## AC-5: Responsive Layout
```gherkin
Given the user views the About page on mobile (< 768px)
When the contact section is visible
Then the form stacks vertically and remains usable
And touch targets meet minimum 44x44px sizing
```

<!-- audit-added: AC-6 through AC-8 -->

## AC-6: Accessibility
```gherkin
Given the user interacts with the form using a keyboard or screen reader
When validation errors are present
Then each invalid field has aria-invalid="true"
And each error message is linked to its field via aria-describedby
And a live region (aria-live="polite") announces success/error status
And focus moves to the first invalid field on validation failure
And all form interactions are keyboard-operable
```

## AC-7: Privacy Disclosure
```gherkin
Given the user views the contact form
When the form is visible
Then a privacy notice is displayed below the submit button
And it states that form data is processed by Web3Forms (third-party service)
And it provides context on how the data will be used (to respond to inquiries)
```

## AC-8: Spam Protection
```gherkin
Given a bot attempts to submit the form
When the hidden honeypot field is filled
Then the submission is silently rejected by Web3Forms
And legitimate users never see or interact with the honeypot field
```

<task type="auto">
  <name>Task 1: Create ContactForm component</name>
  <files>src/components/ContactForm/ContactForm.jsx, src/components/ContactForm/ContactForm.css</files>
  <action>
    Create ContactForm React component:
    - Three visible fields: name (text), email (email), message (textarea)
    - Controlled inputs with React state
    - Client-side validation on submit:
      - Name: required, min 2 characters
      - Email: required, validate with pattern `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` <!-- audit-added: explicit regex -->
      - Message: required, min 10 characters
    - Input sanitization: strip HTML tags from all field values before submission using a simple regex `.replace(/<[^>]*>/g, '')` (no dependency needed) <!-- audit-added -->
    - Inline error messages below each field when invalid

    Accessibility requirements: <!-- audit-added -->
    - Each input must have a visible `<label>` with matching `htmlFor`/`id`
    - Error messages must have unique IDs, linked to inputs via `aria-describedby`
    - Invalid fields must have `aria-invalid="true"`
    - On validation failure, focus must move to the first invalid field
    - Success/error status messages must use `aria-live="polite"` region
    - All interactions must be keyboard-operable (tab order, Enter to submit)

    Anti-spam protection: <!-- audit-added -->
    - Add a hidden honeypot field: `<input type="checkbox" name="botcheck" style={{display:'none'}} tabIndex={-1} autoComplete="off" />`
    - Web3Forms automatically rejects submissions where botcheck is filled
    - The honeypot must be invisible to users and unfocusable

    Submit handler:
    - POST to Web3Forms API (https://api.web3forms.com/submit)
    - API key sourced ONLY from environment variable: `import.meta.env.VITE_WEB3FORMS_KEY` <!-- audit-added: no hardcoding -->
    - If key is missing, log error and show user-friendly message instead of crashing
    - Send JSON body: { access_key, name, email, message, botcheck }
    - Use AbortController with 10-second timeout on fetch <!-- audit-added -->
    - On timeout, transition to error state with message "Request timed out, please try again"
    - Use ref-based submission lock (useRef) to prevent double-submit, not just button disable <!-- audit-added -->
    - Generate a client-side UUID per submission and include as `submission_id` custom field for traceability <!-- audit-added -->

    Form states: idle, submitting (disable button + loading indicator), success, error
    - Success state: show confirmation message, clear fields
    - Success auto-clear timer: use useEffect with cleanup on unmount to prevent memory leaks <!-- audit-added -->
    - If user begins typing during success state, cancel auto-clear and transition to idle <!-- audit-added -->
    - Error state: show error message, preserve field data
    - Log submission attempts and outcomes to console.info (no PII in logs — log only status and submission_id) <!-- audit-added -->

    Privacy notice: <!-- audit-added -->
    - Below the submit button, render a small text:
      "Your information is sent via Web3Forms and used only to respond to your inquiry."
    - Style as muted text (--white-ghost, small font size)

    Style with ContactForm.css matching design system:
    - Use CSS custom properties from global.css (--black-surface, --border, --ember, --white, --f-body, --f-mono, etc.)
    - Input styling: dark background (--black-elevated), subtle border (--border), white text
    - Focus states: ember border glow
    - Error states: ember colored error text
    - Submit button: ember background, uppercase Syne font, hover glow effect
    - Smooth transitions using --t-base and --ease-out
    - Responsive: full-width on mobile, touch targets minimum 44x44px

    Avoid: Adding any npm dependencies. Use native fetch API for submission.
    Avoid: Hardcoding the Web3Forms access key in source code.
  </action>
  <verify>
    - Component renders without errors
    - Form validation prevents empty/invalid submissions
    - Visual inspection matches design system
    - Honeypot field is invisible and unfocusable
    - aria-invalid, aria-describedby, and aria-live attributes are present in DOM
    - Tab through form confirms keyboard operability
    - API key is read from import.meta.env.VITE_WEB3FORMS_KEY, not hardcoded in source
    - console.info logs appear for submit/success/error (no PII)
  </verify>
  <done>AC-1 satisfied: Form renders with all fields. AC-2 satisfied: Validation with inline errors. AC-6 satisfied: Accessible form interactions. AC-7 satisfied: Privacy notice present. AC-8 satisfied: Honeypot field active.</done>
